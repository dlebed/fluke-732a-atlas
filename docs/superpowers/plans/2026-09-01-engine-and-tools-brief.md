# Engine and tools adaptation — brief

Read `docs/superpowers/specs/2026-09-01-732a-atlas-design.md` first. This
document is the concrete work list for turning the copied 5700A engine and
pipeline into the 732A Atlas. The reference project (read-only, for diffing
and for understanding intent) is the `fluke-5700a-troubleshooter/` checkout
alongside this one; its `CLAUDE.md`, `README.md`, `data/schema.md` and
`.claude/skills/add-assembly/SKILL.md` explain how the two halves fit.

Storage keys and format strings were already rebranded mechanically
(`fluke5700a.` → `fluke732a.`, `fluke5700a-` → `fluke732a-`).

## A. Engine (`index.html`, `js/`, `css/`, `assets/brand/`)

1. **Rebrand prose.** `<title>732A Atlas</title>`; brand model "732A";
   `document.title` prefix "732A Atlas — "; default unit model `'732A'`
   (units.js, three places); service.js export file name
   `732A-<serial>-service-<stamp>`, import error wording, report instrument
   default and footer ("Generated by the Fluke 732A Atlas. Expected values
   are quoted from the 732A Instruction Manual, P/N 645051, May 1983…");
   caps.js export file name `732a-replacement-caps.tsv`; every user-visible
   "5700A"/"calibrator" becomes "732A"/"reference standard". Comments that
   record *why* something was built may keep their 5700A history.
2. **Brand mark.** A new mark for an atlas: keep the 32×32 outline square, but
   inside it draw a compass needle (a slim diamond, north half in `--fluke`
   colour, south half in `currentColor`, small centre dot). Update the inline
   SVG in `index.html` and the four files under `assets/brand/` plus its
   README so they match.
3. **Symptoms tab.** The `faults` mode button reads `S<u>y</u>mptoms` and is
   bound to key `Y` (F is released). Panel heading "Symptoms — Table 4-2",
   card labels: *Probable cause* (`measure`), *Action* (`verdict`); empty
   state "The manual lists no symptom that points at <id>."; the help/overview
   text that mentions the Fault codes tab follows. The data key stays
   `faultCodes`; entries carry `code` (short id such as `S3`), `title` (the
   symptom), `measure`, `verdict`, `refs`, `source`.
4. **One- and two-sided limits** in `js/testpoints.js`: a state may carry
   `{ min }`, `{ max }` or `{ min, max }` (numbers, same unit as the point).
   `range()` returns `{ lo, hi, nominal, tol, kind: 'min'|'max'|'minmax' }`
   with `lo = -Infinity`/`hi = Infinity` for the open side, nominal = the
   midpoint for `minmax` and the bound for one-sided, `tol` = half the width
   for `minmax` and 5 % of |bound| for one-sided. `evaluate()`: outside →
   `fail`; inside and within 10 % of the band width (one-sided: within
   `tol`) of a limit → `marginal`; else `pass`; `deviation` is measured −
   nominal; `pctOffNominal` null for one-sided. `formatRange()` prints
   `≤ 60 V`, `≥ 24 V`, `+24.5 … +26.5 V`; `formatNominal()` prints the same
   for one-sided and `+25.5 V ± 1` for `minmax`. `hasExpectation()` and
   `states()` include min/max. Every consumer that reads `state.nominal`
   directly (testlog, procedures, service report, author inspector) must
   still work — grep for `nominal` and `tolerance` and follow each use.
   The Author inspector exposes `min` and `max` fields for a test point.
5. **Links.** An item may carry `link: { assembly: 'A3', ref: 'TP1' }` (ref
   optional). The detail dock / info card shows a button "Open A3 ›" (label
   uses the target dataset's id and name); pressing it switches the assembly
   picker to that dataset and, if `ref` is given and exists there, selects
   it and focuses it. Followers (linked view) follow as they do for any
   selection.
6. **Picker order.** `BoardExplorer.list()`: ids with no digits sort first
   (alphabetically), then numeric order as now.
7. **Sheets without `grid`.** Any sheet may omit `grid`; the zone label is
   then absent everywhere (card, author inspector, sheet tabs, zone frame).
   No exception may be thrown for such a sheet — audit every use of
   `.grid` in `app.js`, `author.js`, `viewer.js`.
8. **Kinds.** In `app.js` the two prefix→kind maps and the three kind maps:
   `DS`→`led`, `FL`→`part`, `XF`→`mech`, `J`→`connector` (a connector on
   this instrument, not a jumper), `P`→`connector`, `E`→`terminal`,
   `HR`→`heater`, `BT`→`battery`, `T`→`transformer`, `S`→`switch`,
   `W`→`wire`, `RT`→`thermistor`, `MP`/`H`→`mech`. New kinds `terminal`
   (colour in the grey/blue family near `connector`) and `heater` (warm, near
   `thermistor`) with labels "Terminals" and "Heaters" in `KIND_COLORS`,
   `KIND_LABELS` and `kindLabel`'s names.
9. **No photograph.** With a dataset whose `layers` has only the drawing,
   Author Mode's *Photo landmarks* and *Align outline* controls are replaced
   by one line, "This board has no photograph yet — drop one in as
   `assets/<asm>/photo.jpg` and it can be aligned here.", and nothing in
   `author.js` or `app.js` throws. Photo / Overlay / Swipe stay disabled as
   they already are.
10. **Sanity.** `node --check` every file. Run the smoke recipe from the
    reference SKILL.md (vm-load `parts.js`, `caps.js`, then a dataset) against
    a small synthetic dataset you write to a scratch directory, with a
    `SYS`-style id, a sheet without grid, a `min`-only test point and a
    `link`, to prove the load path and `TestPoints.evaluate` work.

## B. Pipeline (`tools/`, `data/schema.md`)

The curated inputs per dataset `<asm>` ∈ {a3, a4, a5, sys}:

| File | Holds |
|---|---|
| `data/<asm>.board.json` | `id`, `name`, `pca`, `pcb` (e.g. "732A-1003"), `rev`, `refs` ({locator, schematic, parts, theory, troubleshooting}), `layers` (drawing only: `{id:'drawing', label, src, credit, transform:'identity'}`), `schematics` (sheets: `{id, title, src, figure, grid?}`) |
| `data/<asm>.parts.json` | `components: [{ref, kind, desc, fluke, mfrCode, mfrPart, qty, notes, esd, star, page}]`, ranges already expanded, one entry per designator |
| `data/<asm>.procedures.json` | `procedures: [{id, title, source, prereq, warnings, steps: [{n, text, refs, measure?}]}]` — `measure` optional: `[{point:'TP5', ref:'TP1', ...expectation}]` |
| `data/<asm>.testpoints.json` | as the reference schema (`rails`, `testpoints`, `probePoints`) plus the new `min`/`max` forms |
| `data/<asm>.reference.json` | `overview`, `railCircuits`, `functions` (ref → what it does), `faultCodes`, `warnings`, `caveats`, `foreignStepRefs`, `tables` |
| `data/<asm>.caps.json` | as the reference |
| `data/<asm>.coords.json` | generated by `build_coords.py` |
| `data/<asm>.coords.overrides.json` | hand corrections, plus a new `confirm: [refs]` list that marks a read position as `verified` without retyping it |

1. **`assemble.py`.** Rewrite around those inputs. Remove the 5700A `SHEETS`
   table and every per-assembly special case; take identity and sheets from
   `board.json`, components and procedures from their files, and keep the
   generic merge logic (components ← coords; test points ← coords; rails ←
   testpoints + reference railCircuits; functions; faultCodes; caveats;
   tables; `foreignStepRefs`; `capAudit`; `notOnDrawing`; the coverage
   figures the app reads). Header comment names the 732A sources. Output
   `data/<asm>.js` calling `BoardExplorer.register({...})` exactly as before.
   `link` on a component or test point passes through untouched.
2. **`check_data.js`.** Accept `min`/`max` as an expectation (one of
   nominal/maxAbs/min/max, with a source); a `minmax` with `min >= max` is an
   error; keep every existing invariant. Also check that every `link.assembly`
   names a dataset that exists as `data/<id>.js` (case-insensitive file name)
   and that `link.ref`, when given, exists in it. Default assembly argument:
   none — require one, or `all` to check every `data/*.js`.
3. **`ocr_designators.py`.** `VALID_PREFIX` gains `DS FL XF T S W RT E BT HR
   J P`. `known_designators()` reads `data/<asm>.js` if built, else falls back
   to `data/<asm>.parts.json` + `data/<asm>.testpoints.json`. Everything else
   unchanged; it must run under `/usr/bin/python3` (3.9) and use `magick`.
4. **`build_coords.py`.** Add a third source between OCR and overrides:
   `.build/<asm>/vlm_<space>.json`, shape
   `{"space":"board","image":{"w":W,"h":H},"entries":[{"ref":"C1","x":..,"y":..,"w":..,"h":..,"refined":true}]}`
   in pixels of that space's `_full.png` (x,y = box centre). A designator the
   reader did not place takes the VLM entry with `placement: 'vlm'`; one the
   reader did place keeps the reader's box unless the two disagree by more
   than a box width, in which case the VLM box wins and placement is
   `ambiguous`. Overrides still win over both. Honour `confirm: [...]` in the
   overrides (placement → `verified`, geometry unchanged). Add `vlm` to the
   tiers the app labels: in `js/app.js` `PLACEMENT`, "read by a vision model
   from the drawing; confirm before trusting" — coordinate with section A
   (it is one line; add it yourself if the engine agent has not).
5. **`extract_assets.sh`** is already rewritten for the 732A (do not touch).
   `spaces.py` stays. `review_markers.py`, `page_grid.py`, `text_only.py`,
   `detect_round_parts.py`, `qa_overlay.py`, `fold_overrides.py`,
   `fold_bundle.py`: make sure each runs from this repository under
   `/usr/bin/python3`, references no 5700A path or name, and that
   `fold_bundle.py` accepts the `fluke732a.author.bundle` format string.
   `make_release.sh`: default name `fluke-732a-atlas`; the release README it
   writes carries the 732A safety wording (battery peak current, mains on A3)
   and no xDevs photo credit (there are no photographs).
6. **`data/schema.md`.** Rewrite for this project: the file table above, the
   new expectation forms, `link`, `confirm`, the `vlm` tier, `SYS`.
7. **Prove it.** Build a tiny synthetic dataset `data/zz.*.json` (delete it
   afterwards) through `assemble.py` and `check_data.js`, including a `min`
   point, a `link`, a sheet without grid, and a `vlm` placement; show the
   output loads in node with the same vm recipe as section A.10.

## C. `tools/vlm_place.py` (new)

A vision model cannot be called from a script; it is reached through agents.
So the tool prepares the question and consumes the answer:

```
tools/vlm_place.py plan  <asm> <space> [--grid CxR] [--tile-width 1400] [--only C1 R5 ...] [--all]
tools/vlm_place.py merge <asm> <space> <answers.json> [--no-refine]
tools/vlm_place.py render <asm> <space> [--out path]     # markers from vlm_<space>.json drawn on the image, tiled for review
```

- `plan` reads `.build/<asm>/<image>_full.png` (via `spaces.py`), determines
  the designators still unplaced in that space (known designators from
  `data/<asm>.js` or the parts/testpoints files, minus what
  `data/<asm>.coords.json` already places there; `--all` asks for every
  designator, `--only` for a list), cuts the image into `C×R` overlapping
  tiles (15 % overlap) downscaled to `--tile-width` px, draws a labelled grid
  on each tile every 100 tile-pixels with the label being the **full-image
  pixel coordinate** of that line, and writes `tiles/<space>/tile_r_c.png`
  plus `manifest.json` under `.build/<asm>/vlm/` recording each tile's
  offset, scale, and the list of designators to look for. It prints the
  question an agent should answer per tile.
- `merge` takes `answers.json`: `{"tiles": {"tile_0_1": [{"ref": "C3", "x": 5620, "y": 2210}, …]}}`
  with x, y in **full-image pixels** (as read off the grid labels). It
  dedupes a designator reported in overlapping tiles (keep the report
  nearest a tile centre), then refines each point unless `--no-refine`:
  threshold the full image, find the connected ink components within 90 px
  of the point whose height is between 18 and 110 px (lettering at 600 dpi),
  merge those whose vertical ranges overlap into one box, pad by 6 px; if
  none qualify keep a 140×70 box at the point and mark `refined: false`.
  Writes `.build/<asm>/vlm_<space>.json` in the shape section B.4 gives.
- `render` draws every entry as a box with its ref and tiles the result
  (like `review_markers.py`) so a person can check them.
- `/usr/bin/python3` (3.9), PIL, numpy, scipy only. Tests: run on
  `.build/a3/drawing_full.png` with `--all --grid 3x3` and check the tiles
  and manifest exist; fake an answers file with two points and merge it.
